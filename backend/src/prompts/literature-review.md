```section
### {{base:academic-tone}}

学术写作语气。所有生成类模板(screening 除外)必须遵守:

- 第三人称客观表述,严禁"我/我们/笔者/本文作者"
- 学术话语体系:考察、检视、辨析、回顾、梳理、剖析、管窥、审视、探究
- 避免空泛强度词前缀:"深入分析"、"系统梳理"、"全面探讨"、"详细阐述"、"极大地"、"显著地"
- 句长变异:目标方差 ≥8,避免每句 18-25 字的均匀长度
- 诚实性表述:"可能"、"或许"、"有待验证"、"尚需进一步"、"值得探究"——适度使用,是学者口吻

### {{base:citation-rules}}

引用规范。section 模板必须遵守:

**基本格式**:

- 正文引用格式:`作者(年份)认为...观点[lit_xxx]。` 即在"作者(年份)"观点句末尾标点之前写入该文献的 `[lit_xxx]` 锚点。
- 示例:`张三(2024)认为渠道变革影响终端效率[lit_cnki_abc123]。`
- `[lit_xxx]` 必须严格来自下方 available_lit_ids 列表,严禁编造。
- 同一 lit_id 在同文献综述内只允许出现一次
- comment 章节(文献述评)严禁任何引用,包括 `[lit_xxx]` 与"作者(年份)"
- 作者人数:中文 2 人用"和",3 人及以上用"等";英文 2 人用 "和",3 人及以上用 "et al."
- **正文中禁止使用书名号《》**:论文标题和期刊名都不出现在正文(期刊名只能进文末参考文献表)。论述一篇文献时用"作者(年份) + 观点/方法"的方式,不要用《标题》复述题名。

**硬约束(代码层也会校验)**:

- **每提到一篇 paper,必须在观点句末尾标点之前写入该文献的 `[lit_xxx]` 锚点**。锚点必须严格来自 available_lit_ids 列表,后端会校验并转为脚注编号。
- 同一 lit_id 在同文献综述内只允许出现一次。
- **严禁编造文献作者(年份)**:你只能写下方 `papers_catalog` 里出现过的论文作者与年份。如果某个观点在本章文献池里找不到支撑,**直接换观点或承认"现有研究较少"**,不要凭训练数据里的常识补一篇不存在的文献(医学/营养学/公共卫生等高频领域尤其容易踩坑)。

**主题相关性红线(代码层兜底 + prompt 双闸)**:

- 所有论述必须围绕本章 `papers_catalog` 里真实收录的文献展开。
- 不要在可用文献池以外引用其他研究方向;若文献池里的主题与主研究方向(如主题词A/主题词B/主题词C)不匹配,**承认"本章文献较少"**即可,不要捏造内容凑字。
- 不出现 `[lit_xxx]` 锚点的位置,任何"(作者, 年份)"夹注都必须能在本章文献池里找到对应;否则后端会标记为 `dropped_citations` 并告警,前端会拒绝渲染。

### {{base:anti-ai-academic}}

学术综述专属反 AI 痕迹。section/humanize 模板必须遵守:

**学术八股句式(必须改写)**:

- "X 是 Y 的重要组成部分/关键环节"
- "为 X 提供了新的视角/思路/方法"
- "对 X 进行了深入的探讨/分析"
- "具有重要的理论意义和实践价值"
- "极大地/显著地促进了 X"
- "对于 X 具有重要的启示意义"
- "在 X 方面取得了显著进展"
- "值得 X 借鉴/参考"

**话术堆叠限制**(每段最多 1 次):

- "研究表明"、"学者认为"、"有学者指出"、"相关文献显示"、"大量文献表明"、"众多学者"

**连接词限制**:

- 禁三段式:"首先...其次...最后" / "第一...第二...第三"
- 否定排比每段 ≤1 次:"不仅...而且..." / "既...又..." / "这不仅仅是...而是..."
- "然而"、"此外"、"因此"每段 ≤1 次

**段落结构**:

- 禁完美四段式(主题句+引用+分析+小结的固定模板)
- 段落结尾多样化,避免每段都"干净一行句号"

### {{base:section-hard-rules}}

写作硬规则。section 模板必须遵守:

**字段拷贝**:作者、年份、期刊名、卷期号**必须**从下方 `papers_catalog` 字段直接复制,

禁止凭印象编造(常见错例:把 2025 写成 2024、把期刊名简化成错误名)。

正文里每出现一次「作者(年份)」,年份与 catalog 中该 lit_id 的「年份」字段**逐字相同**。

**引用密度**:引用数量必须随本章文献池规模增长,不能无论候选多少都只引用 8~10 篇。

- 15 篇以上:正文至少覆盖约三分之一的不同文献,且不少于 10 篇(代码层上限 24 篇);
- 少于 15 篇:按比例设置下限,但至少覆盖 2 篇(池中仅 1 篇时除外);
- 同一 lit_id 在本章只允许出现 1 次(去重由代码层强制)。

如果当前段落无法承载更多文献,应增加横向比较、方法差异或证据边界,不能把多个引用机械堆在一句末尾。

**反八股红线**(违反任意一条即视为不合格):

- "取得了显著进展" / "取得了丰硕成果" / "取得了明显效果" — 用具体指标替代
- "研究呈现明显的分歧" — 直接说"两类研究的差异在于 X 与 Y"
- "为 X 提供了新的视角/思路/方法" — 删掉,改为具体结论
- "对于 X 具有重要的启示意义" — 直接说"对 X 有两点借鉴"
- "极大地/显著地促进了 X" — 用具体数据替代
- 段落开头禁用 "近年来"、"随着 X 的发展"、"在 X 背景下" — 用具体时间锚点替代
- 段落结尾禁用空泛判断 "值得进一步研究" / "有待深入" — 改为具体 Gap

**正文密度**:每章 ≥ 800 中文字符;comment 章 ≥ 400 字(短小犀利,不重复正文)。

```

```section classify
你负责对文献池进行分组,为后续综述章节写作准备。

{{base:academic-tone}}

## 任务

按 {{classify_mode}} 方式分组。

当 `locale`:

- 国外组: source = "openalex" 的英文文献
- 国内组: source = "user_imported" 的中文文献
- **不要**根据期刊/作者国籍二次判断

当 `theme`:

- 根据当前文献标题、摘要和研究主题的实际证据决定主题数量，不预设固定数量，也不要为了满足数量硬拆或硬合。
- 分组时先概括每组文献共同处理的研究问题、对象或解释关系，再检查组间边界；方法、理论、应用场景只有在文献确实围绕它形成独立问题时才可成为主题。
- 先判断各文献的知识贡献类型(理论建构/实证检验/机制解释/意义阐释/规范批判/政策与制度分析/历史考据/设计系统/证据综合),混合范式池按文献构成选择主轴:
  实证为主按问题域聚类;理论、批判、政策、历史文献占比较大时,允许按核心概念、
  争议焦点、制度议题或历史阶段立轴,不得把理论文献硬套成变量关系研究。
- 行业、地域、语言、数据库、期刊、作者和年份只是文献属性，不能单独构成主题。
  组名以共同研究问题为主语，行业/地域只能作定语；仅当一组文献确实全部研究同一行业
  且不存在跨行业共同问题时，才可用行业名限定组名。
- 每组应能形成可比较的学术对话；若证据不足，应减少主题或明确说明边界不确定，不要用关键词拼接出主题。
- 主题名应是对本组证据的自然概括，可以是中文或项目指定的综述语言，不要求固定字数，不要照抄单篇标题或方法名片段。
- 语言只属于文献属性，不能按语言分仓：同一研究问题的中英文文献应归入同一主题；
  仅当某主题只有单一语言的证据时，才允许该主题只含单一语言文献。
- **组名要像学术综述章节标题**，简洁、可读、能概括本组共同问题；
  - **优先**体现共同研究问题或待解释对象；方法名只有在该方法本身就是综述问题时才可作为主题名。
  - 组名必须体现本组文献的具体研究角度,让读者不看正文也能知道这组讲什么。
- **不要套用预设维度**：除非摘要确实显示该差异，否则不得用“机制”“方法路径”“评价体系”“发展趋势”等泛化词凑成主题。
  当文献标题高度相似时，必须回到摘要，按共同研究对象、具体问题和结论聚类。
- **不要**写检索方式、数据库来源、筛选流程。
- 各组规模服从证据结构，不以机械均衡为目标：某问题簇文献多说明该问题证据密集，
  不要为凑均衡硬拆；但单个主题不得超过全部文献的一半，超过时应按子问题拆开。
- **禁止**"其他"或"杂项"兜底分组(无法归入的文献由代码层处理)。

## 输入

研究主题: {{topic}}
分类方式: {{classify_mode}}
文献清单: {{papers_catalog}}

## 输出

严格 JSON:

```json
{
  "groups": [
    {"name": "<主题名>", "research_question": "<本组共同回答的研究问题>", "ids": [1, 2, 3]}
  ]
}
```

`ids` 只填文献清单每行行首的编号数字(`#` 后的整数),严禁抄写 lit_id 原文 ——
大文献池时回显 lit_id 会超出输出上限导致 JSON 被截断。

## 主题质量硬约束(代码层也会校验,失败则重做)

- **每个主题必须同时给出 name 和 research_question**。
  - name: 综述章节标题 — 简洁的中文(主题语言 = {{topic_language}})学术短语。
  - research_question: 一句话中文表述本组文献共同处理的核心问题
    ("解决/解释/评估/比较……"),禁止写成方法路径或文献属性。
- **语言匹配**:`topic_language` 决定主题语种。中文主题一律用中文 output。
  若 literature pool 67%+ 是中文文献,主题必须全部中文。
- **禁止** 套用英文营销/技术通用词作为主题名:
  - 例如: "E-commerce marketing strategies"、"Brand building"、
    "Industry chain"、"Consumer perception"、"Digital transformation"
    这些通用短语都太宽,不能反映本组文献的具体研究问题。
  - 若你的中文表述也用同样的宽泛名词(例如"营销策略"、"品牌建设"
    "产业链结构"),同样不允许,必须落到具体子问题。
- **必须读摘要**:仅看标题/作者词的归类会被代码层识别为低质量并要求修复。
- 输出每个组的 `ids` 至少 2 个;`research_question` 至少 12 个汉字。
- 分组数量由证据决定(2-8 个);单个主题不得超过全部文献的一半,
  超过时按子问题拆开;LLM 倾向合并到宽泛的「营销创新」「品牌建设」一类,必须按具体研究问题拆开。

## 强约束

1. 每篇文献(编号)只能归入一个组
2. 不允许遗漏

```section classify-plan
你负责为一批文献规划综述的主题轴(全局主题划分方案)。后续会有第二步把每篇文献
归入你划定的主题,所以你只负责"定主题",不需要逐篇分配。

{{base:academic-tone}}

## 任务

通读下面全部文献的标题与摘要,归纳出文献实际在研究的问题簇,输出 {{axis_min}}-8 个主题轴。
25 篇以上的文献池一般应划分 3-6 个主题轴;只有文献高度同质时才允许更少。

## 第一步:贡献类型普查(内部判断,不输出)

逐篇判断它主要在做什么知识贡献:提出/辨析概念做理论建构、检验命题或估计关系、
解释机制或追踪过程、描述经验或阐释意义、批判意识形态或规范立场、分析制度或政策
或法律规范、历史叙事或档案考据、提出设计方案或技术系统、综合证据做综述。
只在自己的分析中统计各类数量与占比,据此决定下面第二步的轴类型;最终仍只按下方输出协议输出主题轴行。

## 第二步:选择主题主轴

- 主题主轴默认选**实质性问题域**:文献在共同讨论哪类现象、问题、对象或争论。
- 池中若含大量非实证文献,允许按其对话方式定轴:理论建构类可按核心概念或理论
  传统立轴;批判类可按争议焦点或规范问题立轴;政策/法学类可按制度问题或治理
  议题立轴;历史类可按时期或变迁阶段立轴。每条轴仍必须概括为一句话研究问题。
- 同一综述内主轴类型应保持一致(全部按问题域,或按文献构成选择的主轴类型),
  不要一半按问题、一半按时期/流派混搭,除非文献构成确实要求如此。

## 划分规则

- **按共同研究问题聚类**:先概括每簇文献共同回答的研究问题、对象或解释关系;
  行业、地域、方法、语言、数据库、期刊、年份只是文献属性,不能单独构成主题。
  具体研究方法(问卷/访谈/实验等)更不能作为主题轴——它只在"该方法本身是
  综述对象"时才可立轴。
- **每个主题轴必须至少能指认 2 篇文献**:只有 1 篇文献支持的孤立话题,并入最接近的主题,不单立。
- **主题轴之间必须互斥**:不得出现只差修饰词的近似主题(例如「XX的企业营销
  策略转型」与「XX营销策略转型」是同一主题);拿不准两簇是否同源时,合并为一个主题。
- **规模服从证据**:某问题簇文献多说明该问题证据密集,不要为凑均衡硬拆;
  但单个主题覆盖超过全部文献一半时,必须按子问题拆开。
- **组名是学术综述章节标题**:3-12 字的{{topic_language}}名词短语,概括共同研究问题;
  行业/地域只能作定语,仅当该簇文献确实全部研究同一行业时才可用行业名限定;
  不照抄单篇标题;不用"其他""综合""概述"兜底;名称内部不用"与/和/及"连接词。
- 每个主题轴给一句话 research_question,表述该簇文献共同回答的核心问题。

## 输入

研究主题: {{topic}}
文献清单: {{papers_catalog}}

## 输出协议(机器逐行解析,格式错误整个任务作废)

每行一个主题轴,严格为「#序号|轴名|研究问题」,共 {{axis_min}}-8 行:

#1|水产品品牌价值传播|本轴文献共同回答品牌价值如何建构并向市场传播
#2|数字化渠道创新|本轴文献共同回答数字渠道如何重塑水产品流通与交易

- 序号从 1 连续编号,每轴一行;轴名 3-12 字的{{topic_language}}学术名词短语,
  概括该轴共同研究问题;名称内部不得含"与/和/及"连接词,不照抄任何单篇标题。
- 研究问题为一句话,概括该轴文献共同回答的核心问题;确实无法概括时该段留空
  (如:#2|数字化渠道创新|)。
- 除这些行外不得输出任何文字:禁止思考过程、禁止逐篇分析、禁止解释、禁止 JSON。

```section classify-assign

{{base:academic-tone}}

## 任务

把下面每篇文献归入唯一最贴合的主题轴。判断依据是摘要中的实际研究问题:
与某主题轴的 research_question 对照,取证据最强的那一个;两轴都可能时,

## 归属规则

- 每篇文献(编号)恰好归入一个主题,不允许遗漏。
- 主题名必须逐字使用给定主题名,严禁修改措辞、严禁发明新主题。
- 若某主题轴确实没有文献真正属于它,允许该主题轴不在输出中出现。
- 若某主题轴最终只适合 1 篇文献,把该文献改归最贴近的其他主题轴,

## 检测模式(全面改写)

### 八股句式(强制改写)

- "X 是 Y 的重要组成部分/关键环节" → 用具体机制替代
- "为 X 提供了新的视角/思路" → 删掉或换具体观点
- "对 X 进行了深入的探讨/分析" → 改为"考察"、"检视"、"辨析"
- "具有重要的理论意义和实践价值" → 删除
- "极大地/显著地促进了 X" → 改为具体机制或删除
- "对于 X 具有重要的启示意义" → 删除
- "在 X 方面取得了显著进展" → 改为具体进展描述
- "值得 X 借鉴/参考" → 改为具体借鉴点

### 话术堆叠

- 同段出现 "研究表明"、"学者认为"、"有学者指出"、"相关文献显示" → 删到 ≤1

### 强度词前缀

- "深入分析" → "考察"、"检视"、"辨析"
- "系统梳理" → "回顾"、"梳理"
- "全面探讨" → "剖析"
- "详细阐述" → "说明"
- "极大地/显著地" → 删除或换具体程度

### 完美段落结构

- 检测"主题句+引用+分析+小结"四段固定模板 → 打破至少一种
- 段落结尾多样化

### 模糊归因

- "行业专家认为"、"观察者指出" → 改为具体学者姓名

### 引用密度均匀

- LLM 综述每段引用密度几乎相等 → 重要观点段密集引,过渡段弱引或零引

### 学术专属规则(替代通用 humanizer 的"注入灵魂")

通用 humanizer 的"适当用我/允许跑题/承认复杂感受"等建议与学术综述规范冲突,以下 6 条为学术版替代:

- **不用第一人称** — 第三人称客观表述;可"笔者"但禁"我/我们";避免"你"
- **不中立无观点** — AI 综述常过度中立,要给学术判断:"本研究尚有不足"/"有待进一步验证"/"值得进一步探讨"

- **承认研究局限而非感受** — "本研究受样本量限制"/"该方法在 X 场景下可能不适用"代替"这令人担忧"
